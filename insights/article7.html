Least Privilege for AI Agents: How to Scope Access Without Breaking the Workflow

AI agent governance · 9 min read

At 4:12 on a Friday afternoon, a finance agent stopped halfway through the month-end close. It had reconciled 311 invoices, flagged three duplicates, and then hit the one step it could not do: post the adjusting entries. Its just-in-time elevation had expired at 4 p.m., the human approver was on a train, and the close slipped to Monday. In another company the same week, a support agent with standing write access to the customer database did the opposite — it finished the job nobody asked it to do, emailing a customer list to a vendor whose address it had guessed from a thread. One agent could do too little. The other could do too much. Both failures had the same cause: nobody had scoped what the agent was allowed to touch, and nobody had built the mechanism that would have caught it.

Least privilege for AI agents is the oldest idea in security applied to the newest kind of actor. The principle has not changed since the 1970s: give each actor only the access its task needs, for only as long as it needs it, and take it back when the task ends. What has changed is that the actor now decides for itself what to do next, which means the scoping cannot live in a policy document. It has to live in the request path, enforced by machinery the model cannot talk its way around.

Start with identity, not permissions

Permissions attached to a borrowed login are not permissions at all. An agent running on a developer's credentials inherits the developer's authority, and every action it takes is indistinguishable from the human's. The fix that every serious framework now starts with is a separate identity for each agent, with its own credential lifecycle and a named human owner. NIST's 2026 guidance, "Design Tenets for Agent Identity Management Systems," states it as the first of ten tenets — distinct agent identification — and adds the sentence that has become the field's motto: guardrails alone are insufficient. Deterministic identity, dynamic authorization, and token attenuation must sit outside the language model, not inside it.

The vendors have spent 2026 building exactly that. Okta for AI Agents became generally available in May 2026, with Agent SSO following in August; each agent is registered in the Universal Directory as its own identity, next to the employees who own it, and Okta's discovery tooling finds shadow agents — including coding agents such as Claude Code and Cursor — that were never registered at all. Microsoft's Entra Agent ID brings agents inside the same Conditional Access, Identity Protection, and Identity Governance controls that cover human users. IBM shipped Agent Identity with HashiCorp Vault 2.2 in October 2026, registering agents in a central inventory with ownership, risk classification, and approved tool connections, and issuing short-lived credentials from Vault so each agent can perform only the actions it was assigned.

Scope by role and task, not by person

Once the agent has its own identity, the scoping question becomes concrete: what may this agent do, to which systems, for which purpose? The working answer is roles defined by task, not by the human who deployed the agent. A research agent reads. A transacting agent moves money within a limit. An approving agent signs off, and never the same agent that requested. NIST's third tenet — least and zero standing privilege — makes the separation explicit: agents hold no persistent rights while idle, get only the minimum scope a task needs, and are kept from combining privileges that conflict, which is separation of duties stated for software.

The cleanest formulation comes from the intent model that Oasis Security built its Agentic Access Management product around in November 2025: each request is read as a structured intent covering resource, operation, scope, and purpose, and access is granted against that intent rather than against a standing role. The agent that may read the CRM to draft a renewal quote is not the agent that may write to the billing system, even when both agents belong to the same team and the same human sponsor. Scope is a sentence about a task, not a badge about a person.

Just-in-time elevation

The hardest part of least privilege is the moment the agent legitimately needs more than its standing scope — the adjusting entry at 4:12 on a Friday. The answer is not to widen the standing role. It is elevation that is just in time, time-limited, and revocable, which is NIST's fourth tenet: no long-lived bearer tokens, no static secrets, runtime checks on every call, and revocation that works while the agent is mid-task.

Three mechanisms do the work. The first is short-lived tokens scoped to a single task and a single audience, issued at call time and dead minutes later — the pattern Aembit uses when its gateway swaps in a scoped credential so the agent never holds the real secret, and the pattern Ory's Talos, launched in June 2026, was built to replace static API keys with. The second is a gateway in the request path that checks policy before every tool call, which is how Okta's Agent Gateway and Microsoft's Entra controls enforce scope even for MCP servers the agent connects to directly. The third is lifecycle discipline on the identity itself: Microsoft's default inactivity rule, in preview, notifies sponsors and owners after 60 idle days, disables the identity at 90, and deletes it at 455. An agent nobody uses stops existing, instead of lingering with its permissions intact.

Audit hooks on every step

Scoping without a record is a promise, not a control. Every elevation, every denial, and every action taken under elevated access has to land in a log tied to the agent's identity — who the agent is, who owns it, what it was allowed to do, what it actually did, and when the permission expired. Access reviews then do for agents what they have always done for employees: a regular recertification that asks whether the agent still needs what it holds, with revocation as the default answer.

The regulators are converging on the same shape from different directions. Canada's OSFI warned in a July 2026 bulletin on generative and agentic AI about over-privileged access and shared or inherited credentials, and pointed to a unique non-human identity per agent, least privilege, just-in-time access with short-lived credentials, logging and review, and periodic recertification; its E-23 guideline takes effect May 1, 2027. Singapore's IMDA published version 1.5 of its agentic AI framework on May 20, 2026, requiring each agent's identity to be unique and cryptographically verifiable, tied to a supervising agent, a human user, or a department, with authority that is scoped, time- or session-bound, and non-transferable. NIST's AI Agent Standards Initiative, announced February 17, 2026, made agent security and identity one of its three pillars. Three jurisdictions, one pattern: identity, scope, expiry, record.

When it goes wrong

The failure modes are worth naming, because they are the reason least privilege programs stall. The first is over-scoping: permissions drawn so tight that the agent cannot finish ordinary work. The symptoms are easy to spot — agents stalling mid-task, humans pasting credentials into chats to unblock them, teams quietly building shadow agents outside the registry. Every workaround an agent's owner invents to get past a tight scope is a permission granted without a record, which is worse than the broad scope it replaced.

The second is the opposite: scope creep by accretion. An agent gets a temporary elevation for a project, the project ends, the elevation stays. Six months later the agent holds the sum of every temporary grant it ever received, and nobody reviews the total because nobody reviews combinations. Palo Alto Networks' 2026 survey put machine identities at 109 to 1 against humans; at that ratio, manual review of every agent's permissions is not a process, it is a fantasy. The review has to be automated, scheduled, and tied to the identity lifecycle, or it will not happen.

The counterargument: least privilege is a tax on speed

The honest objection is that least privilege slows agents down, and the objection is not wrong. An agent that must request elevation for every write action is an agent that stops and waits. A team that scopes every tool call is a team that ships its first agent weeks later than the team that handed the agent the service account and moved on. And there is a real argument that agents need broad read access to be useful at all — an agent that can only see the three records its role names cannot notice the pattern across the other three hundred.

The answer is to scope the writes and be generous with the reads. Reads are reversible; writes are not. An agent that can read broadly and write narrowly, with elevation for the write step and a human in the loop above a risk threshold, keeps most of the speed and most of the safety. NIST's tenets say the same thing in their own way: human-in-the-loop triggers should route risky actions to the right reviewer without causing consent fatigue, because a human asked to approve everything approves nothing carefully. The tax is real. The way to pay less of it is to charge it only where the damage lives.

What to do on Monday

Four moves, in order. First, inventory every agent in production, including the ones developers set up without asking — the shadow fleet is where the unscoped access lives. Second, give each agent its own identity with a named human owner, and retire every shared credential and borrowed login the fleet runs on. Third, replace standing write access with just-in-time elevation: short-lived, scoped, logged, and revocable mid-task. Fourth, put the audit hook on every elevation and review the scopes on a schedule, not when something breaks.

The companies that do this will not notice the difference on a good day. That is the point. Least privilege is invisible when it works — the agent finishes the close, the elevation expires at 4 p.m. because the close is done, and nobody emails a customer list to a stranger. The alternative is also invisible, right up until the Friday it is not.
